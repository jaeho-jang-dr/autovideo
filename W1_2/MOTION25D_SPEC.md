> 담당: **무비랑**(제작 총괄) · **캐릭터랑**(캐릭터 자산) · **컷랑**(프레임컷)

## 0. 이 회차에서 새로 된 것 / 안 된 것

| | 결과 |
|---|---|
| **전·후방 걷기·달리기** | ✅ 됐다. Flow 영상 → 프레임컷 → 투명컷 → 키 통일 |
| **좌·우 걷기·달리기** | ✅ 됐다 (한 방향 만들고 반전으로 반대쪽) |
| **좌표를 이용한 사선 이동** | ✅ 됐다. 옆모습/전후 컷을 쓰면서 **x·y·키를 함께 옮긴다** |
| **완벽한 45도 사선 전용 컷** | ★ **실패**. Flow 가 고정 각도를 못 낸다([[flow-fixed-angle-fails-use-rotation]]) |

★45도 사선은 **전용 컷을 만들려 하지 말 것.** 8초·10초 프롬프트를 여러 번 시도해도
Flow 는 각도를 고정하지 못한다. 각도는 **참조 이미지가 정하고**, 회전은 잘 되므로
회전 영상을 뽑아 원하는 각도 프레임을 골라내는 편이 빠르다.
사선 **이동**은 아래 §3 처럼 **좌표 연출**로 해결한다 — 그림이 아니라 배치의 문제다.

## 1. 원근 — 키가 자리를 정한다

화면(1280×720)에서 캐릭터 키와 발 y 는 한 쌍으로 움직인다. W1-2 확정값:

```
FOOT = {90:490, 200:540, 250:556, 322:590, 420:648, 480:672, 520:682, 600:700}
FAR=90  MID=420  NEAR=520  HUGE=600      # 스틱맨 기준 화면 키(px)
```

* **키를 줄이면 반드시 발 y 도 함께 올려야 한다.** 키만 줄이면 허공을 걷는다.
* 배경마다 지평선이 다르므로 무대는 `stage2d.Stage(<배경키>)` 에게 물어본다.
  씬이 제 나름의 상수를 들고 있으면 그때뿐이다.
* 지평선은 **사람 발밑으로 눈으로 짚어 잰다.** 자동 검출은 나무·물보라를 사람으로
  잡는다([[stage-horizon-measure-by-feet]]).

## 2. 걸음 수와 이동 거리 — 보폭 공식

멀어질수록 한 걸음이 화면에서 짧아진다. 그 관계:

```
β = ALPHA × k / FOCAL                     # ALPHA 0.85(달리기) · FOCAL 1108
strides(ya→yb) = |1/(ya−HOR) − 1/(yb−HOR)| / β
y_at(ya,yb,u)  = HOR + 1/( 1/(ya−HOR) + (1/(yb−HOR) − 1/(ya−HOR))×u )
```

* `y_at` 로 위치를 보간해야 **등속으로 보인다.** 선형 보간하면 멀리서 빠르고
  가까이서 느려 보인다.
* 한 스트라이드 = 0.30초(달리기)·0.40초(걷기) 가 W1-2 기준값.

## 3. 사선 이동 — 전용 컷 없이 만드는 법

비트 하나에 **x·키·발y 를 동시에** 준다. 컷은 그 방향의 옆모습/전후 것을 쓴다.

```python
# 오른쪽 저 멀리 → 왼쪽 앞으로 (사선 진입)
(0.0, 3.4, "m6:run_side_l", 1300, 700,  90, 420)
#            ↑ 왼쪽 보는 컷   x1300→700  키90→420 (발y 는 FOOT 이 따라온다)
```

* 컷의 **얼굴 방향과 이동 방향이 같아야** 한다. 오른쪽으로 가는데 왼쪽 보는 컷을
  쓰면 뒷걸음질로 보인다.
* 계단처럼 **위로 가는 사선**은 뒷모습 컷 + x 고정 + 키 감소로 만든다(§5 계단).

## 4. 컷 재생 속도 — fps 가 발놀림을 정한다

비트 튜플의 9번째 값이 **컷 재생 fps**다. 좌표·시간과 **독립**이다.

```
(2.0, 8.5, "run_front", 640,640, 190,420, 440,660, 18.0)
                                                    ↑ 컷 fps
```

* 이동 속도를 바꾸지 않고 **발놀림만** 빠르게/느리게 하려면 이 값만 만진다
  (사장님 지시 "좌표 이동속도가 아니라 스트라이드 속도를 두 배로").
* 컷 N장이 한 스트라이드면 `fps = N / 스트라이드초` 가 원속이다.

## 5. 방향별 쓰임새 (W1-2 실전)

| 상황 | 컷 | 좌표 |
|---|---|---|
| 저 멀리서 정면으로 달려옴 | `run_front` | 키 90→460 |
| 계단을 뒷모습으로 올라감 | `walkback`(투명컷 10장) | x 고정 · 키 420→190 · 발 660→440 |
| 계단을 정면으로 내려옴 | `run_front` @18fps | 키 190→420 |
| 옆으로 걸어 들어옴 | `walk_side_l/r` | x 만 이동 · 키 고정 |
| 물 터널 왕복 | `run_back_r` → `run_front_r` | 키 177→49→177 |
| 화면 밖으로 사라짐 | `run_back` | x→1460(화면 밖) · 키→12 |

★**돌아서기는 되도록 쓰지 않는다.** 사장님 확정 — "돌아서기가 아주 어색하다".
뒷모습이 필요하면 처음부터 뒷모습 컷으로 간다.

## 6. 배경 길이가 모자랄 때

* **되감기(ping-pong) 금지.** 사람이 뒷걸음질하고 물줄기가 거꾸로 빨려 든다.
* 배경 동영상 = 각 프레임을 N번씩 물려 **느리게 정방향**으로 흘린다(`BG_SLOW`).
* 캐릭터 동선이 든 씬 = 끝 프레임 유지. 다만 **애초에 씬 길이를 나레이션에 맞추는**
  것이 정답이다.

## 7. 배경 사건과 말을 붙이는 법

블록을 **씬 하나 단위로** 쪼갠다. 그래야 씬 길이를 바꿔도 사건 시각이 안 밀린다.
W1-2 에서 좌판을 한 덩어리(68초)로 뒀다가 우유 낙하가 12.5초 어긋났다.

```
좌판  → 오이(S8+S9 48초) / 우유(S10 20초)     우유 낙하 = 블록 +6.6초 고정
노을  → 노을(S23 14초)   / 등(S24 16초)       마지막 등 = 블록 +7.9초 고정
```
