# W23 동작 시나리오 계획 — 방향 우선 설계 (2026-07-28)

> 사장님 확정 원칙: **캐릭터는 언제나 화면 중앙을 향한다.** 위치가 먼저 정해지는 게 아니라
> **자산의 방향이 먼저 정해지고, 그 방향이 중앙을 보도록 위치를 잡는다.**

---

## 1. 방향 원칙 (위반 금지)

| # | 원칙 |
|---|------|
| P1 | 캐릭터가 **왼편(Z30 x=384)** 에 서면 → 시선·팔·가리킴은 **오른쪽(중앙)** |
| P2 | 캐릭터가 **오른편(Z66 x=845)** 에 서면 → 시선·팔·가리킴은 **왼쪽(중앙)** |
| P3 | 방향이 반대인 포즈밖에 없으면 **좌우 반전(flip)** 해서 쓴다 |
| P4 | 동작 동영상은 **그 영상의 이동 방향을 먼저 확정**하고, **이동해 갈 방향의 반대편에 세워** 시작한다 |
| P5 | 파라메트릭 글자는 **캐릭터의 반대편**에 렌더한다 (캐릭터 왼편 → 글자 오른편) |
| P6 | **글자 뒤에 얼굴·몸을 두고 서 있으면 안 된다.** 걸어서 **지나가는 것은 허용**(순간 통과), 정지 상태의 겹침만 금지 |
| P7 | **걷기가 끝나면 반드시 정면 또는 약간 측면(3/4)으로 돌아선다.** 측면(프로필) 그대로 서 있는 상태 금지 — 걷기 컷은 전부 측면이므로 정지 시 반드시 정지 포즈로 전환 |
| P8 | 파라메트릭 글자는 **가능한 한 많은 한글**을 보여준다. **1줄·2줄·3줄 모두 허용** (기존 "배경 동영상 씬은 1줄 제한" 규정은 해제 — 가독성만 확보되면 늘린다) |

## 2. 자산 방향 태그 (실측 완료)

### 2-1. 정지 포즈 16종 — 몸통중심 대비 팔 뻗침(px, 원본 1024 기준)

| 방향 | 포즈 | 뻗침 | 세울 위치 |
|------|------|------|-----------|
| **→오른쪽** | `present_right` 281 · `point_board` 230 · `hand_on_post` 230 · `lean_rail` 227 | 우세 | **왼편 Z30** |
| **←왼쪽** | `present_left` 252 · `explain` 183 · `tap_board` 181 · `count_three` 166 · `thumbs_up` 143 · `raising_hand` 141 | 우세 | **오른편 Z66** |
| **중립** | `bow` · `hard_smile` · `invite_hand` · `lean_bench` · `nod_agree` · `phone_calendar` | 대칭 | 양쪽 가능 |

> 중립 6종은 배경 앵커·글자 위치에 맞춰 자유 배치. 방향 포즈는 반대편에 놓아야 할 때 flip.
> 인준 복장(네이비 티·베이지 바지·흰 운동화)은 좌우 대칭이고 글자·로고가 없어 **flip 티가 안 난다.**

### 2-2. 동작컷 12종 — 이동/주 동작 방향

| 유형 | 클립 | 실측 | 배치 규칙 |
|------|------|------|-----------|
| **실이동** | `run_slide_in` | 원본 +430px (왼→오른) | **왼쪽 밖에서 시작 → 중앙/오른쪽 착지**. 도입·등장 전용 |
| **방향성** | `board_write` → 오른쪽 · `spin_phone` ← 왼쪽 | 뻗침 편중 | 뻗는 쪽이 중앙이 되게 배치 |
| **대칭(양쪽)** | `backflip_land`374 · `onehand_freeze`428 · `railing_vault`385 · `greet_wave`361 · `point_far_follow`322 · `catch_petal`298 · `jump_highfive`265 · `lean_back_surprise`250 · `check_ok`217 · `follow_parade`232 | 좌우 대칭 | 양쪽 가능. **최대 뻗침 × 0.561 만큼 화면 여백 확보 필수** |

> ★주의: 컷랑 정규화가 매 프레임 몸통중심을 중앙정렬해 **이동 성분을 지운다.**
> `run_slide_in` 외에는 컷에 이동이 없다 → 이동이 필요한 씬은 **합성 단계에서 x를 이동**시켜 만든다.

### 2-3. 잘림 여유 계산 (CHAR_SCALE 0.561)

| 클립 | 최대 뻗침(원본) | 캔버스 환산 | Z30(384) 왼쪽 여유 | Z66(845) 오른쪽 여유 |
|---|---|---|---|---|
| `onehand_freeze` | 428 | 240 | 144 ✅ | 195 ✅ |
| `railing_vault` | 385 | 216 | 168 ✅ | 219 ✅ |
| `backflip_land` | 374 | 210 | 174 ✅ | 225 ✅ |
| `greet_wave` | 361 | 203 | 181 ✅ | 232 ✅ |

→ 전 클립 양쪽 배치 가능. 단 `run_slide_in`은 이동 폭 430×0.561=241px를 더 봐야 한다.

## 3. 씬 배정 절차 (이 순서로만)

```
① 씬의 콘텐츠 방향 결정   — 글자(파라메트릭)를 어느 쪽에 둘지
② 캐릭터 위치 결정        — 글자의 반대편 (P5)
③ 포즈/동작 선택          — 그 위치에서 중앙을 향하는 방향 태그를 가진 자산 (P1·P2)
④ 방향이 없으면 flip      — (P3)
⑤ 동작 동영상이면 시작 위치 역산 — 이동 방향의 반대편 (P4)
⑥ 배경 앵커 실좌표에 맞춰 서는 x 미세조정 — 손이 난간·기둥·게시판에 닿게
⑦ 검증 게이트 통과 후 렌더
```

## 4. 검증 게이트 (렌더 전 자동 검사)

| 검사 | 기준 | 도구 |
|------|------|------|
| 방향 위반 | 캐릭터 위치와 자산 방향 태그가 같은 쪽이면 FAIL | `audit_w23_scenes.py` 확장 |
| 잘림 | 인물 알파가 화면 밖 1px이라도 나가면 FAIL | `check_char_fit.py` |
| 글자 겹침 | **정지 구간에서** 글자 박스와 인물 알파 교집합 > 0 이면 FAIL (걷기 통과 구간은 면제) | 신규 |
| 측면 정지 | 걷기 종료 후 정지 포즈로 전환 안 하고 측면 컷이 3프레임 초과 유지되면 FAIL | 신규 |
| 앵커 접촉 | 손끝과 배경 앵커 거리 > 40px 이면 WARN | `check_w23_anchor.py` |
| 자산 미사용 | 동작컷 12종 중 미배정이 있으면 FAIL | `audit_w23_scenes.py` |

## 5. 작업 순서

1. **방향 태그 테이블을 DB에 기록** (`anim_char_poses` 확장 또는 별도 테이블)
2. **36씬 배정표 재작성** — 동작컷 12종 전원 배정, 씬당 동작 2개 연결 허용
3. **좌향 flip본 생성** — 방향 포즈 10종의 반대편 버전
4. **배경 앵커 실좌표 측정** → 씬별 서는 x 확정
5. **검증 게이트 통과**
6. `build_w23.py` 작성 → DB 구축 → 나레이션 TTS → 렌더
